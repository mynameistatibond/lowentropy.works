1. Overview & Goals

What this spec covers and what the MVP shell must achieve

This document specifies the frontend technical implementation of the IU AI Studio MVP main page shell. It covers the authenticated user experience after login — the persistent layout frame, navigation system, account controls, and dashboard content scaffold. No AI functionality is implemented in this phase; the spec defines the application chrome and page structure that all subsequent features will be built within.

Goal Description
Establish layout chrome Persistent top bar, sidebar, and content grid that all MVP screens share
Role-aware entry point User's selected role is reflected in UI — sidebar, greeting, quick actions
Navigation foundation All primary destinations are accessible and correctly routed
Account & session User identity, role badge, settings, and logout accessible from any page
Notification surface Bell icon with badge count — no notification logic yet, just the UI
Design token baseline All colors, type, spacing, and elevation defined as CSS variables
Responsive shell Works at 1440px (desktop), 1024px (laptop), 768px (tablet)
Accessibility baseline WCAG 2.1 AA contrast, keyboard navigation, ARIA landmarks

The shell must feel fast, intentional, and professional from day one. First impressions set adoption expectations — a polished chrome earns trust before a single AI feature is live.

2. Tech Stack

Recommended technologies for the MVP frontend shell

The following stack is recommended for the MVP shell. It prioritizes developer velocity, component reusability, and maintainability over architectural novelty. The stack should be finalized with the engineering team before implementation begins.

Framework

Technology Role / Rationale
React 18+ Component model, concurrent rendering, Suspense for lazy loading
Next.js 14 (App Router) Routing, SSR for initial load performance, layouts for persistent shell

Styling

Technology Role / Rationale

CSS Custom Properties Design tokens (colors, spacing, radius) defined as var(--) globally
shadcn/ui components Accessible, unstyled primitives (Dialog, Popover, DropdownMenu, Tooltip)

State Management

Technology Role / Rationale
Zustand Lightweight global state for: auth session, sidebar collapsed state, notifications
React Context Role context — UserRoleContext provided at layout root
TanStack Query Server state for notifications count, user profile fetch

Auth

Icons & Assets

next/image Optimized image component for avatar and brand mark
Geist font (Vercel) Clean, modern typeface for dashboard UI — available via next/font

Testing & Quality

Technology Role / Rationale

Note on CSS: All design tokens must be defined as CSS custom properties in a globals.css file before any component styling begins. Tailwind config extends these tokens. No hardcoded hex values in component files — always reference vars.

3. Page Layout Architecture

Layout zones, grid structure, and responsive behavior

3.1 Layout Grid & Zone Map

The authenticated shell is divided into four persistent layout zones labeled A–D. These zones are defined at the root layout level (Next.js app/layout.tsx) and remain constant across all authenticated pages. Only Zone C (main content) changes per route.

  • ZONE A — TOP NAVIGATION BAR
  • ZONE B — LEFT SIDEBAR NAV
  • ZONE C — MAIN CONTENT: Welcome Header · Quick Action Grid · Recent Activity · Announcements
  • ZONE D — CONTEXT PANEL (AdvisorWidget)

The layout uses CSS Grid at the root level with named template areas. Zone B and D are position:sticky so they remain fixed during content scroll.

/* globals.css — root authenticated layout */
.app-shell {
  display: grid;
  grid-template-rows: var(--topbar-height) 1fr;
  grid-template-columns: var(--sidebar-width) 1fr var(--rightpanel-width);
  grid-template-areas:
    "topbar topbar topbar"
    "sidebar main rightpanel";
  min-height: 100vh;
}

/* CSS token defaults */
--topbar-height: 56px;
--sidebar-width: 240px;
--sidebar-collapsed-width: 64px;
--rightpanel-width: 280px;
--content-max-width: 1200px;

3.2 Responsive Breakpoints

Breakpoint Mode Behavior
1440px+ Full All 4 zones visible. Sidebar expanded (240px). Right panel visible.
1280px Standard desktop All 4 zones. Sidebar expanded. Right panel collapsed to icon-only.
1024px Laptop 3 zones. Sidebar collapsed to icons (64px). Right panel hidden.
768px Tablet 2 zones. Sidebar hidden; hamburger menu opens as overlay drawer.
< 768px Mobile (future) Out of scope for MVP. Shell must not break — graceful degradation only.

56px persistent header · logo · search · notifications · account

The top navigation bar is 56px tall, spans the full viewport width, and sits at z-index 100 above all other content. It uses the app's darkest background (--color-surface-dark) with a subtle 1px bottom border. All child components described in this section live within a flex row with justify-between.

  • Asset: SVG logotype — horizontal lockup (icon + wordmark). White on dark.

4.3 Global Search Bar

In MVP the search bar is a non-functional UI placeholder that establishes the visual pattern for future search capability. It must look complete and intentional — not a disabled or grayed-out element.

  • Width: min(480px, 40vw). Centered horizontally in the top bar.
  • Height: 36px. Border-radius: 8px. Background: --color-surface-elevated (slightly lighter than topbar).
  • Left icon: Lucide Search, 16px, --color-text-muted.
  • Placeholder: 'Search tools, tasks, prompts…' in --color-text-muted.
  • Keyboard shortcut hint: '⌘K' displayed as a small badge on the right side.
  • Click/focus: opens a CommandPalette modal (empty shell, no results in MVP).
  • PostHog: fire search_bar_focused event on focus.

4.4 Notification Bell

  • Icon: Lucide Bell, 20px stroke, --color-text-secondary.
  • Badge: Red dot (8px circle) in top-right corner. Shows count '3' as static placeholder in MVP.

  • Popover contains: header 'Notifications', empty state illustration, 'Mark all read' button (disabled).
  • PostHog: fire notification_bell_clicked on open.

4.5 User Account Menu

The account menu is the user's primary identity surface and settings gateway. It must be clearly recognizable and immediately accessible from any page.

Trigger (closed state):

  • Name: First name only, displayed inline. Hidden at < 1100px viewport width.
  • Chevron: Lucide ChevronDown, 14px. Rotates 180° on open (CSS transition 150ms).

Dropdown (open state) — DropdownMenu component:

  • User block: Non-clickable. Avatar (40px) + full name + email + role badge.
  • — 1px separator line.
  • My Profile: → /profile · Lucide UserCircle icon
  • My Workspace: → /workspace · Lucide LayoutDashboard icon
  • Settings: → /settings · Lucide Settings icon
  • — 1px separator line.
  • AI Certifications: → /certifications · Lucide Award icon · Badge showing level
  • — 1px separator line.
  • Sign Out: Calls signOut(). Lucide LogOut icon. Destructive text color.

Dropdown width: 240px. Offset: 8px below trigger. Border: 1px --color-border. Shadow: var(--shadow-lg). Border-radius: 10px. Animation: fade + slide-down 120ms ease.

5. Zone B — Left Sidebar Navigation

240px · role-aware · collapsible · sticky

The sidebar is the platform's primary navigation surface. It is always visible on desktop and collapses to icon-only mode at 1024px. On tablet it becomes an overlay drawer. The sidebar background uses --color-sidebar (near-black navy) to visually separate it from the main content area and reinforce the platform's professional identity.

5.1 Role Indicator

Immediately below the top bar boundary, the sidebar displays a role indicator block. This is the user's selected role — it is not a navigation item.

  • Height: 48px. Full sidebar width. Background: slightly lighter than sidebar (--color-sidebar-hover).
  • Content: Small colored dot (role color) + role name text + 'Change role' link (12px, muted).
  • Role colors: Lecturer → blue, Marketing → teal, Admin → orange, Legal → red, HR → purple, Support → green.
  • Hover on 'Change role': navigates to /role-select to re-enter role selection flow.
  • Collapsed state: shows only colored dot, no text.

5.2 Navigation Items

Navigation is grouped into two sections separated by a divider: primary navigation (core platform areas) and secondary navigation (settings, help). Each item follows the same anatomy.

Item Anatomy:

  • Height: 40px. Full sidebar width. Border-radius: 8px (inset 4px from edges).
  • Layout: 16px left padding → icon (20px) → 10px gap → label text → optional right badge.
  • Active state: --color-accent background, white text and icon.
  • Hover state: --color-sidebar-hover background (transition: 100ms).
  • Focus state: 2px --color-accent outline (keyboard navigation).

6. Zone C — Main Content Area

Dashboard home · welcome · quick actions · recent · announcements

Zone C renders the authenticated dashboard home page — the screen a user sees immediately after login. It is the most important screen in the MVP for establishing platform value and directing user intent. All sub-components in this zone are scaffolds: they establish layout and visual structure but contain placeholder or static data.

6.1 Welcome Header

  • Full-width top block within Zone C. Background: --color-surface (white/off-white).
  • Height: auto (~80px). Padding: 24px top and bottom, 32px left.
  • Left: Greeting text 'Good morning, [First Name].' (H1, 22px, --color-text-primary).
  • Sub-text: 'You're signed in as [Role].' with role badge inline. 14px --color-text-secondary.
  • Right (optional): Date + quick stats strip: '3 saved prompts · 2 team updates' in muted text.
  • Bottom border: 1px --color-border-light.
  • Greeting changes by time of day: 'Good morning' / 'Good afternoon' / 'Good evening'.

6.2 Quick Actions Grid

The quick actions grid is the primary entry point for task-based navigation from the dashboard. It surfaces the 6 most relevant tasks for the user's current role. In MVP these are static — role-to-tasks mapping is hardcoded in a config object.

  • Section label: 'Quick Actions' in 11px uppercase tracking-widest --color-text-muted. 24px top margin.
  • Grid: 3 columns × 2 rows at 1440px. 2 columns at 1024px. Gap: 16px.
  • Card size: auto height (~100px). Full width within column. Border-radius: 12px.
  • Card anatomy: Icon (28px, colored per category) + Task label (14px bold) + short descriptor (12px muted, 1 line max).
  • Card background: white. Border: 1px --color-border. Box shadow: var(--shadow-sm).
  • Hover: shadow lifts to var(--shadow-md), border-color shifts to --color-accent. Slight translateY(-2px). Transition: 150ms.
  • Click: navigates to /tasks/[task-type] — routes are defined but pages show 'Coming soon' scaffold.
  • PostHog: fire task_card_clicked with task_type property on click.

9. Component States

All interactive states that must be implemented in MVP

Every interactive element in the shell must implement all of the following states. Incomplete state coverage is a bug, not a backlog item — states should be built alongside the component, not added later.

  • Navigation Item: default, hover, active (current page), focus (keyboard), disabled (no access)
  • Quick Action Card: default, hover (shadow lift), active/pressed, focus (keyboard), loading (skeleton)
  • Account Menu: trigger: default, hover, focus | dropdown: open, closing | menu item: hover, focus, active
  • Search Bar: default (placeholder visible), focused (ring highlight), ⌘K hint visible always
  • Notification Bell: default (badge shown), hover, popover: open, empty state
  • Sidebar Item: default, hover, active, focus, tooltip (collapsed mode only)
  • Collapse Toggle: expanded icon state, collapsed icon state, hover, focus
  • Feedback Button: default, hover, modal open state (empty shell)
  • Advisor Entry Card: default, button hover, button active, button focus

Loading states: Every data-driven section (recent activity, notifications count, user name) must show a Skeleton shimmer loader while data is fetching. Use shadcn/ui Skeleton component with var(--color-border-light) base and a shimmer animation. Never show empty divs during loading.

10. Accessibility Requirements

WCAG 2.1 AA — non-negotiable for a university platform

As an institutional platform serving faculty, staff, and students, WCAG 2.1 AA compliance is a legal and ethical requirement — not an enhancement. All MVP shell components must meet or exceed these requirements before release.

Color Contrast

  • All text on light bg: minimum 4.5:1 contrast ratio (WCAG AA).
  • Large text (18px+ or 14px bold): minimum 3:1 ratio.
  • Sidebar text on dark bg: all items must meet 4.5:1 — verify --color-sidebar vs text.
  • Use Figma Contrast plugin or webaim.org/resources/contrastchecker to verify all combos.

Keyboard Navigation

  • Full tab order through all interactive elements — no keyboard traps.
  • Sidebar navigation fully operable via Tab + Enter.
  • Account menu: open via Enter, navigate items via Arrow keys, close via Escape.
  • Skip-to-main-content link: first focusable element on page (visually hidden, shows on focus).
  • Quick action cards: navigable via Tab, activated via Enter or Space.

ARIA Landmarks & Roles

  • <header> for Zone A (top bar).
  • <nav> for Zone B sidebar.
  • <main> for Zone C content area.
  • <aside> for Zone D right panel.
  • aria-current='page' on active sidebar nav item.
  • aria-expanded on account menu trigger. aria-haspopup='menu'.
  • role='menu' and role='menuitem' on account dropdown items.
  • Notification bell: aria-label='Notifications, 3 unread'.

Focus Management

  • Opening account menu: first menu item receives focus automatically.
  • Closing menu (Escape): focus returns to trigger button.
  • Opening mobile sidebar drawer: first nav item receives focus.
  • Closing drawer: focus returns to hamburger button.
  • Search bar modal open: focus moves to search input.

Reduced Motion

  • All transitions and animations must respect prefers-reduced-motion.
  • Wrap animation CSS in @media (prefers-reduced-motion: no-preference) {}.
  • Advisor pulse animation: disabled in reduced motion mode.
  • Sidebar collapse transition: instant in reduced motion mode.

Screen Reader

  • Test with VoiceOver (macOS) and NVDA (Windows) as part of QA.
  • Avatar initials fallback: aria-label='User avatar for [Full Name]'.
  • Role badge in sidebar: aria-label='Current role: [Role Name]'.
  • Skeleton loaders: aria-busy='true' on parent containers while loading.
